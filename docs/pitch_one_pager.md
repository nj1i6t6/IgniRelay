# 烽傳 IgniRelay — 一頁式專案簡介

> **當 4G 斷線、WiFi 消失、光纖挖斷——這支 App 讓倖存者彼此找到彼此。**

---

## 問題

台灣位處地震帶，921、0206、花蓮強震等歷史災難一再證明：**基礎通訊在重大災害後數小時內即可能全面癱瘓**。此時政府 EOC（緊急應變中心）無法掌握受災現場，民眾無法求援，物資無法配對，每一分鐘的資訊斷層都是潛在的生命損失。

現有的解決方案（衛星電話、無線電）成本高、單點、不具擴展性，**一般民眾無法使用**。

---

## 解決方案

**烽傳 IgniRelay** 是一套以手機為節點的去中心化災難通訊與物資媒合系統。

手機透過藍牙 BLE 自組 Mesh 網路，在沒有任何網際網路的條件下：

- 📡 **傳遞 SOS 訊號**：訊息逐跳轉送，擴大覆蓋範圍
- 🎒 **物資媒合**：自動比對附近的供需雙方（水、食物、藥品、電池），並以 4 碼 PIN 完成實體交接確認
- 🗺️ **離線戰術地圖**：內建台灣 MBTiles 向量圖，標示危險區域、物資點、路況
- 🔐 **身份信任體系**：從匿名（Day 1 可用）到公民數位身份（TW FidO），4 級信任梯次
- 🏘️ **行政區地理圍欄**：訊息依村里行政邊界路由，對齊緊急應變單位的管轄範圍

## 技術亮點

| 層次 | 技術 |
|------|------|
| 行動前端 | Flutter（iOS + Android 跨平台） |
| 網路層 | 自研 BLE GATT Mesh，雙角色 Central/Peripheral |
| 抗衝突同步 | Hybrid Logical Clock（HLC）+ CRDT 離線合併 |
| 效能優化 | Bloom Filter 差異同步、Triage Queue（SOS_RED 搶佔頻寬） |
| 加密 | Ed25519 數位簽章，每則訊息可驗真偽 |
| 後端（恢復期） | Node.js + PostgreSQL/PostGIS，EOC 指揮儀表板（React） |
| 資料格式 | Protocol Buffers（非 JSON），低功耗高效率 |

## 尋求的合作

| 類型 | 說明 |
|------|------|
| 場地 / 環境 | 需要在有多人參與的場域做 BLE Mesh 真實壓力測試（目前僅限 3～4 台手機） |
| 硬體資源 | LoRa 模組、Sub-1GHz RF 設備、樹莓派等邊緣計算節點的借用/測試 |
| 數位孿生 / 模擬 | 以數位孿生技術模擬大規模災難場景，驗證 Mesh 覆蓋率與物資媒合效率 |
| 跨域連結 | 防災單位、民防組織、社區據點的使用者測試媒合 |
| 技術顧問 | RF 傳播模型、大規模 BLE 部署經驗 |
